# ТикТокер — техническое задание

Версия 0.1 · 15 ноября 2026 · Предложение, требует обсуждения.
Требования пользователя отделены от стартовых параметров и технических гипотез.

## 1. Область реализации

Конвейер: Twitch → клипы → уникальные моменты → монтаж → проверка → публикация
→ статистика → выкуп. Каждый этап хранит вход, результат, состояние и ошибку.
Сбой публикации не должен запускать распознавание и рендер повторно.

P0 — первая бета; P1 — следующий этап. Сроки указаны в ROADMAP.md.

## 2. Обнаружение клипов — P0

**DET-01.** Список каналов с состоянием наблюдения и последним успешным запросом.
Для теста: shadowkekw; для следующего эфира: ravshann. Статус online/offline
обновляется, а не фиксируется только при запуске.

**DET-02.** Получать клипы через официальный API. Стартовая настройка — опрос
раз в 15 секунд, окно 10 минут, периодическая расширенная сверка. Это параметры
для настройки после теста, а не обещание задержки Twitch.

**DET-03.** Обходить страницы, учитывать округление временных границ и пределы
выборки. Если полнота не обеспечена, показывать ошибку покрытия, а не нулевой результат.

**DET-04.** Хранить clip_id, канал, автора, created_at, first_seen_at, duration,
video_id, vod_offset, ссылку и доступные метаданные. Уникальность по clip_id.
Отдельно хранить эфир и подтверждённость связи клипа с ним: созданный сейчас
клип может относиться к старой записи.

**DET-05.** После перезапуска продолжать с сохранённой точки с перекрытием окна.
Первые найденные исторические клипы маркировать baseline. Их возраст не считать
измеренной задержкой обнаружения.

**DET-06.** Лимиты, сетевые ошибки и истечение токена обрабатывать повторными
попытками с ограничением и видимым статусом. Ключи не включать в логи.

## 3. Объединение клипов — P0

**MOM-01.** Единица конвейера — момент с собственным устойчивым ID и набором
клипов. Добавление позднего дубля не создаёт новую задачу рендера/публикации.

**MOM-02.** Совпадение created_at само по себе не является основанием склейки.
Первый сигнал — пересечение интервалов одной записи одного канала. Стартовая
гипотеза: попарное перекрытие не менее 60% короткого интервала и ограниченный
общий диапазон. Пороги настраиваются по размеченным примерам.

**MOM-03.** Не объединять произвольные цепочки пересечений. Разные соседние
события должны оставаться раздельными. В редакторе предусмотреть разделение
ошибочной группы и объединение пропущенных дублей.

**MOM-04.** При пустом VOD/offset повторно запрашивать метаданные. Если есть
исходники — подтверждать совпадение по аудио/последовательностям кадров.
До подтверждения — статус «требует проверки»; не отправлять неоднозначные
кандидаты в автоматическое производство нескольких одинаковых роликов.

**MOM-05.** Выбирать представительный клип по полноте сцены: подводка,
кульминация, завершение. Самый длинный клип — только временная эвристика.
Показывать причину выбора и альтернативные исходники.

**MOM-06.** Для расширения границ нужен доступный VOD/буфер. Если источника нет,
показывать предел доступного материала. Не обещать восстановление отсутствующих кадров.

## 4. Медиа и монтаж — P0

**VID-01.** Отдельно подтвердить источник скачивания и требуемую авторизацию.
Доступ к метаданным не означает доступ к видеофайлу.

**VID-02.** Выход: MP4, H.264/AAC, 1080×1920. Исходное разрешение проверять;
1920×1080 — типичный вход, не обязательное условие. Не растягивать пропорции.

**VID-03.** Шаблоны: игра + камера; разговорный крупный план; без камеры.
Игровое изображение можно сохранить целиком или кадрировать. Пользователь
выбирает вариант в предпросмотре; важные детали не должны теряться незаметно.

**VID-04.** Предлагать границы вебки по нескольким кадрам. Сохранять профиль
канала, проверять смены сцены. При сомнении — ручная рамка. Детекция лица
не считается доказательством границ вебки.

**VID-05.** Два режима субтитров: одно слово; 2–3 слова с подсветкой текущего.
Хранить текст и времена слов отдельно от рендера; редактировать без повторного ASR.
Обрабатывать отсутствие речи, шум, ники и ошибочные распознавания.

**VID-06.** Заголовок между блоками, субтитры в нижней области с отступами
от интерфейса платформы. Редактируются положение, масштаб, текст, начало/конец.
Предпросмотр и итоговый файл используют один рецепт композиции.

**VID-07.** Генерировать описание/хэштеги из подтверждённого содержания,
не выдумывать события. Музыка опциональна, из согласованного источника;
регулируемая громкость и приглушение под речь.

## 5. Проверка и публикация — P0 / зависимость от доступа

**REV-01.** Лента: найденные моменты, обработка, готовы к проверке, одобрены,
отклонены, публикуются, опубликованы, ошибки. Уведомление о готовности и ошибке.

**REV-02.** Карточка: предпросмотр, исходники, авторы клипов, причины группировки,
таймлайн, настройки композиции, субтитры, описание, обложка, аккаунт назначения.

**REV-03.** Одобрение привязано к неизменяемой версии медиа, текста и параметров
публикации. Любая последующая правка создаёт версию, требующую нового одобрения.

**PUB-01.** Публикация только одобренной версии. Получение upload/publish ID
не считать опубликованным постом: проверять конечный статус и сохранять ссылку.

**PUB-02.** При таймауте сначала выяснять статус предыдущей операции. Уникальная
публикация определяется моментом, версией, платформой и аккаунтом. Повторный
пост не создаётся автоматически при неопределённом ответе.

**PUB-03.** Предпочтительный опыт — согласование внутри ТикТокера без второго
редактирования в телефоне. Необходимые настройки платформы доступны пользователю.
Доступ к публичному Direct Post подтверждается отдельным интеграционным тестом.
Резерв: экспорт MP4 и текста. Этот режим явно называется экспортом.

**PUB-04.** Лимиты производства и публикаций независимы. Очередь учитывает
ограничения аккаунта и не пытается обойти их. YouTube — отдельный адаптер P1.

## 6. Статистика и выкуп — P1

**ANA-01.** Сохранять снимки просмотров, лайков, комментариев и репостов
с временем измерения. Не выдавать отсутствие ответа API за нулевые просмотры.

**ANA-02.** Показывать прирост за интервалы, скорость и возраст публикации.
Различать производственные показатели и результат контента.

**BUY-01.** Порог 100 000 и срок 14 дней — предварительные параметры со слов
пользователя, не универсальные правила. До реализации уточнить программу,
начальную дату отсчёта, часовой пояс, ставки/пороги и требования к доказательствам.

**BUY-02.** Рекомендация выкупа учитывает несколько измерений замедления,
следующий порог и запас до дедлайна. Причины видны. Прогноз не гарантирует
отсутствия новой волны просмотров. При нехватке данных — рекомендация проверки.

**BUY-03.** Сначала готовить пакет данных и уведомление. Автоматическая подача
только после определения интеграции и правил; хранить подтверждение и исключать дубли.

## 7. Предлагаемая архитектура

Это проектное решение, не уже существующая система.

| Компонент | Предложение | Назначение |
|---|---|---|
| API и сборщик | TypeScript / Node.js | Twitch, очередь, состояние, публикации |
| Интерфейс | React / TypeScript | Локальный редактор и обзор очереди |
| База | SQLite | Состояние и транзакционные задачи одного пользователя |
| Обработка медиа | Python worker + FFmpeg | Распознавание, кадры, рендер |
| ASR | faster-whisper; при необходимости WhisperX | Речь и времена слов |
| Модель | Заменяемый API-провайдер | Тексты, анализ выборки кадров, предложения |
| Файлы | Локальный каталог output | Исходники, рецепты, версии, результаты |

Выбор Node.js не следует из старого проекта. Он предлагается для общего
TypeScript-стека интерфейса и сервера. Существующий .mjs — эксперимент,
его можно переработать после испытаний. Python используется там, где нужен
медиа/ML-инструментарий. Для беты не нужны микросервисы или Redis.

Модель не управляет всем процессом произвольными командами: возвращает
структурированные предложения с проверяемыми границами. Стоимость и качество
DeepSeek/альтернатив оцениваются на одной тестовой выборке до фиксации провайдера.

Сущности: Channel, StreamSession, SourceClip, Moment, MomentClip, MediaAsset,
Transcript, EditVersion, RenderJob, Approval, Publication, MetricSnapshot,
BuyoutRule, BuyoutSubmission. Job содержит attempt, lease, error, next_attempt_at.
Секреты не входят в эти сущности, отчёты или Git.

Производственное состояние: discovered → grouping → ready_for_processing →
processing → awaiting_review → approved → publishing → published.
Отдельные состояния: needs_input, rejected, failed; ошибки сохраняют этап
возврата. Публикация и выкуп имеют собственные состояния.

## 8. Нефункциональные требования

- Локальный интерфейс доступен только на loopback по умолчанию.
- Секреты и OAuth-токены исключены из репозитория и журналов.
- Очередь переживает перезапуск; завершённые этапы не повторяются без причины.
- Ограничена параллельность тяжёлых задач; видны размер очереди и свободное место.
- Политика хранения исходников настраивается; данные ожидающего выкупа не
  удаляются автоматически до подтверждённого срока хранения.
- Цель — 50 готовых роликов/сутки. Реальное время, диск, память и стоимость
  измеряются на доступном оборудовании; числовое SLA устанавливается по замеру.
- Логи содержат IDs задачи/момента, этап, попытку, время, результат.
- Перенос на сервер возможен без изменения формата рецепта монтажа.

## 9. Приёмка

| Область | Проверка | Условие прохождения |
|---|---|---|
| Сбор | Живой эфир и контрольная выборка | Отчёт о найденных/пропущенных клипах, без заявления о 100% покрытии API |
| Повторы | Один клип в нескольких опросах и после перезапуска | Одна запись и одна обработка |
| Группы | Несколько клипов одной сцены | Один момент, видны все исходники |
| Разделение | Соседние разные события и цепочка пересечений | Разные моменты |
| Нет offset | Свежие клипы без VOD | Неуверенность показана; нет слепой склейки |
| Границы | Подводка/событие/реакция | Проверены человеком; при нехватке исходника есть отметка |
| Монтаж | Игра, разговор, нет вебки | Три корректных примера 1080×1920 без искажения пропорций |
| Редактор | Правка текста, границ и положения | Предпросмотр соответствует финальному MP4 |
| Одобрение | Правка после одобрения | Предыдущее одобрение не разрешает новую версию |
| Публикация | Успех, ошибка, неопределённый ответ | Подтверждённый статус, нет автоматического повторного поста |
| Нагрузка | Репрезентативная очередь | Отчёт о времени/ресурсах и достижимости 50/сутки |

Шесть существующих тестов проверяют только прототип группировки и ingest.
Они не подтверждают готовность продукта или работоспособность живого API.

## 10. Основания и внешние зависимости

Документация проверялась 15 ноября 2026; перед интеграцией проверить снова.

- [Twitch Clips API](https://dev.twitch.tv/docs/api/reference/clips): метаданные,
  отсутствие offset у новых клипов, отдельная авторизация скачивания.
- [Twitch OAuth](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/):
  токен приложения для сборщика; пользовательский доступ для других операций.
- [TikTok Content Sharing Guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines):
  аудит, допустимые сценарии, обязательные настройки и ограничения публикации.
- [TikTok Direct Post](https://developers.tiktok.com/docs/en/content-posting-api-get-started):
  метаданные, обложка, отправка и проверка статуса.
- [TikTok Query Videos](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-query): статистика.
- [FFmpeg](https://ffmpeg.org/ffmpeg-filters.html),
  [faster-whisper](https://github.com/SYSTRAN/faster-whisper),
  [DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/): кандидаты реализации.
