# Проверка обнаружения Twitch-клипов

Независимый диагностический сборщик на Node.js 22+ без npm-зависимостей.
Не публикует, не скачивает медиа, не меняет конфигурацию существующего бота.
Секреты не сохраняются в отчётах. Будущий редактор разрабатывается отдельно
в этом новом проекте; кода редактора старого проекта здесь нет.

## Запуск из корня проекта

Задайте TWITCH_CLIENT_ID и TWITCH_CLIENT_SECRET в окружении либо используйте
локальный JSON вида {"twitch":{"clientId":"...","clientSecret":"..."}}.
Храните этот файл в output/.secrets/, исключённом из Git. Не присылайте ключи в чат.

```powershell
node tools/watch-clips.mjs --channel shadowkekw --credentials-file output/.secrets/twitch.json --seconds 120
node tools/watch-clips.mjs --channel ravshann --credentials-file output/.secrets/twitch.json --seconds 14400
node --test tests/watch-clips.test.mjs
```

По умолчанию интервал 15 секунд, начальная выборка за 60 минут. --seconds 0
выполняет один проход. --lookback-minutes меняет начальную и периодическую
расширенную выборку; --output задаёт отдельную папку состояния.
Сборщик использует lock-файл для защиты от двух процессов в одной папке output.

Результаты: output/clip-watch/<канал>/report.html, state.json и moments.json.
HTML открывается локально, страницу нужно обновлять вручную.
JSON содержит время создания и первого обнаружения каждого клипа.
Первичная выборка — исторический baseline, её возраст не является задержкой
обнаружения нового клипа. Время обнаружения — локальное наблюдение API,
а не точное время доступности клипа в Twitch.

## Реализовано

- OAuth client credentials, чтение канала/статуса эфира, Get Clips.
- Перекрывающиеся окна, пагинация, разбиение больших выборок, учёт округления
  API до минут. При переполнении минутного окна — явная ошибка покрытия.
- Уникальность clip_id, атомарная запись состояния и возобновление.
- Повторный запрос клипов с отсутствующим VOD/offset.
- Группировка по broadcaster + video_id, попарное перекрытие >=60% короткого
  интервала и общий диапазон <=120 секунд. Цепочки пересечений не объединяются.
- Кандидат-представитель: самый длинный клип, затем просмотры; это эвристика,
  не подтверждение полноты сюжета.
- Без таймкодов клипы остаются раздельными, статус awaiting_offset.
- Ограниченные повторы при 429/5xx, обновление app token после 401.

## Ограничения первой проверки

Группы предварительные: нет аудио/видео-подтверждения, смыслового выбора границ
или автоматического монтажа. Их идентификаторы могут измениться при появлении
раннего клипа; не использовать эти ID как ключи производственной очереди.
Stream status обновляется каждые четыре прохода. Общая полнота API не гарантируется;
удалённые/недоступные клипы могут не появиться. Ошибки опроса фиксируются в состоянии
и events.jsonl; следующий проход пробует повторить запрос. Ошибка первоначальной
авторизации останавливает процесс. Один проход (--seconds 0) возвращает ошибку вызывающему.
При --seconds ограничивается цикл наблюдения, текущий запрос/повтор может закончиться позже.

## Проверка

Новые ключи проверены; наблюдение shadowkekw подтверждено реальными данными.
Результаты, задержки и ограничения — в TEST-REPORT-2026-11-15.md.
Старые приложения и конфигурации к этому проекту не подключаются.

После обновления доступа: 2–5 минут наблюдения shadowkekw, затем повторный запуск
для проверки отсутствия дублей; сравнение отчёта с клипами канала. Для проверки
объединения на реальном контенте необходимы несколько клипов одного события.
Если новых клипов не было, это не считается проверкой обнаружения новых событий.
