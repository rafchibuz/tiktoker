# Подготовка исходников и поиск дублей

Медиаэтап после первого одобрения. Один уникальный клип → отдельная задача →
отдельный будущий TikTok. Сборки независимых клипов в один ролик нет.

## Что происходит

1. Пользователь нажимает «Одобрить клип» во вкладке «Новые клипы».
2. Только одобренный клип попадает в постоянную очередь подготовки. Ранее
   автоматически подготовленные исходники сохраняются, но не попадают в монтаж
   до одобрения.
3. Один обработчик получает MP4, проверяет видео/длительность и сохраняет SHA256.
4. Создаёт H.264/AAC-предпросмотр до 1280 пикселей по ширине для браузера.
   Исходник остаётся в исходном разрешении/кодеке, включая HEVC.
5. Вычисляет последовательности низкоразмерных кадров и спектральных признаков звука.
6. Сравнивает с уже подготовленными клипами того же канала.
7. Выдаёт готовый исходник, точный дубль или предложение проверить совпадение.
   Готовый одобренный исходник автоматически переходит в монтаж.

Повторное добавление того же Twitch ID возвращает ту же задачу. Перезапуск
возобновляет незавершённые задачи. Готовые исходники не скачиваются заново.
Отклонение отменяет ожидающую/текущую подготовку; источники не удаляются.

## Правила совпадений

- Одинаковый SHA256 исходного файла: подтверждённый точный дубль, один основной ID.
- Совпадение изображения и звука: только предложение для проверки человеком.
- Можно посмотреть оба исходника, выбрать какой оставить или сохранить оба
  как разные моменты. Это позволяет оставить более полный/длинный фрагмент.
- Совпадение только времени создания не применяется для устранения дублей.
- Статичная картинка или тишина сами по себе не доказывают совпадение.
- В API `render_candidates` содержит только одобренные готовые задачи, исключая
  подтверждённые дубли и спорные совпадения.

Текущая эвристика требует минимум 6 секунд и 60% длительности короткого
клипа, близкую последовательность кадров и спектра. Учитывает временной сдвиг.
Короткие пересечения, изменённый монтаж, замена звука, сильный кроп и почти
статичные сцены могут быть пропущены. Значения сходства — не вероятность.
Полнота/точность на большой размеченной выборке ещё не измерены.

## Получение медиа

Для публичных клипов сейчас используется yt-dlp, без cookies, входа в браузер
или токенов старых проектов. URL строится только из известного ID клипа.
Официальный Helix продолжает использоваться для обнаружения.

Это отдельный адаптер получения публичного видео, а не официальный Twitch
download API. Если клип недоступен, задача показывает ошибку; защиты доступа
не обходятся. Официальный Get Clips Download можно добавить после соответствующей
авторизации стримера/редактора.

Инструменты устанавливаются локально в `.runtime/`, без изменения PATH:

```powershell
powershell -NoProfile -File tools\setup-media.ps1
```

В текущем окружении уже установлены yt-dlp 2026.10.26 и FFmpeg 9.0.2.
SHA256 скачанных пакетов сверен с опубликованными суммами. Скрипт установки
оставляет архив/лицензии в .runtime; этот каталог исключён из Git.

Источники: [yt-dlp](https://github.com/yt-dlp/yt-dlp),
[FFmpeg download](https://ffmpeg.org/download.html),
[Windows builds Gyan](https://www.gyan.dev/ffmpeg/builds/),
[Twitch Clips](https://dev.twitch.tv/docs/api/reference/clips).

## Хранение и ограничения

- Очередь и решения: `output/media-queue.json`.
- На каждую задачу: `output/media/<job_id>/source.mp4`, `preview.mp4`, `fingerprint.json`.
- Ограничение входа: 180 секунд и 500 МБ; запас свободного диска не менее 1 ГБ.
- Одна тяжёлая задача одновременно. Подготовка запускается после одобрения.
- Локальное видео выдаётся через отдельный маршрут с поддержкой Range/перемотки.
- Видео не отправляется в модели или соцсети. Вертикальный монтаж пока не подключён.
- Формат очереди сейчас JSON, один сервер-владелец. Для масштабирования понадобится БД.

## Проверка

Автоматические тесты проверяют уникальность задач, сохранение после перезапуска,
ошибки/повторы, отмену, точные дубли, подтверждение/отклонение похожих моментов,
отсутствие совпадения статичных кадров и Range-ответы локального плеера.

Контролируемый тест реального видео: из 30-секундного исходника сделан фрагмент
с 5,25 секунды длиной 18,4 секунды и перекодирован в 1280×720. Алгоритм нашёл
смещение 5,25 секунды, сходство изображения 0,963 и спектра звука 0,993.
Это положительный тест преобразованной копии, не доказательство качества на
всех независимо созданных зрительских клипах.

Итоговая живая проверка: 9 публичных клипов успешно скачаны, получили
H.264-предпросмотры и проанализированы; два попали в очередь автоматически.
Между девятью клипами совпадений не предложено. Незавершённая задача продолжилась
после перезапуска с тем же ID; готовые задачи сохранились. Это не подтверждает
отсутствие любых дублей на Twitch — проверена только эта выборка.
21 автоматическая проверка проходит. Фактический HTTP-предпросмотр вернул
206 Partial Content с корректным диапазоном. Снимок результата:
`output/media-probe/pipeline-check.json`, тест копии: `crop-match.json` рядом.
Браузерная визуальная проверка ранее была отклонена механизмом разрешений;
новые элементы проверены по API и синтаксису, но не автоматическими кликами.
